Eduwide App

Presentation Flow & Exact Team Task Breakdown

Arranged chronologically from App Start to Advanced Features.

This document presents the Eduwide App features in the exact logical order of the user journey (starting from App Launch & Login). It outlines how the 7-member team distributed these tasks, specifically highlighting the advanced technological implementations and architectures.

Logical App Flow & Task Breakdown

1. Technology Stack & Core Architecture Implementation

Before any UI was built, the foundational technologies, database structures, and platform connections had to be established.

Malitha Tishamal Lead Developer

  • Technology Explanation: Explains the selection of Flutter, Firebase Auth, and Firestore. [High Complexity]
  • Database Design: Designed the NoSQL collections (users, enrollments, zoomMeetings, payments).
  • Firebase Integration: Configured firebase_options.dart and core initialization.
2. User Onboarding (Login, Sign Up & Auth UI)

The first screen the user sees. Handles data capture for Students (A/L Year, NIC) and Teachers.

[Team Member 2 Name] - Auth UI Developer

  • Login & Sign Up Interfaces: Built the visual forms for user registration and authentication. [Low/Medium Complexity]
  • Form Validation: Implemented text controllers, regex validation, and the "Forgot Password" UI.
3. Security, Authentication & Role-Based Routing

Once the user clicks "Login", the backend securely verifies them and routes them to the correct dashboard based on their role.

Malitha Tishamal Lead Developer

  • Firebase Authentication Logic: Engineered the secure sign-in process and session management. [High Complexity]
  • Role-Based Routing: Developed DashboardWrapper which reads Firestore roles in real-time and dynamically routes to Admin, Teacher, or Student dashboards.
4. Admin Portal: User Approvals & Account Management

Because new accounts are "pending", the Admin must log in first to approve new users before they can access the app.

[Team Member 3 Name] - Admin Frontend Developer

  • Admin Dashboard UI: Built the admin_dashboard.dart overview interface. [Medium Complexity]
  • Accounts Management: Created the interface for Admins to view pending accounts, approve them, or lock users.
5. Admin Portal: Adding Students to Classes & Resources

After approval, the Admin assigns students to specific teacher classes.

[Team Member 4 Name] - Enrollment UI Developer

  • Class Enrollment Screen: Built the UI where Admins select a student and enroll them into a class (class_enrollment_screen.dart). [Medium Complexity]
  • Global Resources: Developed the admin_resource_upload.dart interface for uploading study materials.
6. Teacher Portal & Class Management

The Teacher logs in to view their newly enrolled students and prepare for live sessions.

[Team Member 5 Name] - Teacher Frontend Developer

  • Teacher Dashboard UI: Built teacher_dashboard.dart to list enrolled students dynamically by academic year. [Medium Complexity]
  • Teacher Profile: Implemented the profile management screens for educators.
7. Advanced Backend: Zoom Integration & Payment Gateway

Teachers create live classes, and payments must be tracked. This is the most complex logic in the app.

Malitha Tishamal Lead Developer

  • Zoom API Integration: Engineered the backend logic inside zoom_meeting_screen.dart to create, launch, and sync active Zoom meetings directly to Firestore. [High Complexity]
  • Payment Gateway Architecture: Developed the database relations that calculate and track "Pending Payments" vs "Completed Payments" when students are enrolled. [High Complexity]
8. Student Portal: Joining Classes & Viewing Resources

Finally, the Student logs in, sees their classes, checks their payment status, and clicks to join the active Zoom session.

[Team Member 6 Name] - Student Frontend Developer

  • Student Dashboard UI: Built the user_dashboard.dart where students view their enrolled subjects. [Medium Complexity]
  • Joining Meetings & Resources: Created the UI to view resources and launch the Zoom app from the student side.
9. Global UI/UX Theme & Final Quality Assurance

Ensuring the entire flow looks beautiful and runs smoothly on all devices.

[Team Member 7 Name] - UI/UX & QA Engineer

  • Design System: Integrated the AppColors blue theme seamlessly across all 9 steps above. [Low Complexity]
  • Testing: Conducted cross-platform testing to ensure Android, iOS, and Web compatibility worked without bugs.
